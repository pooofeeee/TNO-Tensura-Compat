# Origin, versions and chronology

## Why it started

The external-effects catalog already contained completed, pinned semantic
research. The Alex's Mobs campaign ended at base commit
`dc08cda002029695ff1acc18ce8ed44f0f8ae90f` with a STOP on further mod research.
A separate tooling goal authorized an isolated `feat/mod-intelligence-v1` branch:
retrieve verified mechanics, numeric values, source evidence and dependencies
for future coding tasks, reuse infrastructure and preserve completed research
and production. The research STOP did not prohibit this tooling work.

The original deliverable was a compact, source-checked CLI. Subsequent workflows
exposed unresolved dependency selection, implementation mapping and preservation
bookkeeping. Later goals explicitly asked whether the tooling could reduce
Astra Medium's expensive repeated reasoning while retaining coding quality, and
how that compared with Sol Extra High. These are two related aims—reliable
knowledge reuse and measured coding efficiency—not proof that retrieval alone
reduces model usage.

## V1: trusted retrieval before compression

[V1 documentation](../mod-intelligence-v1.md) defines stable JSON output,
completed-catalog lookup, exact aliases, bounded search, selectable sections,
source-version/hash checks and optional local JAR hashing. Omitting evidence from
output does not omit witness or numeric verification. No extraction, census
rebuild, research regeneration or catalog write is performed.

The first Sugar Rush consumer combined movement, Slow Falling, attribute and
Citadel controller facts into a bounded static Python diagnostic. It showed that
whole-mod dependency output was coarse and lacked selected witness validation,
while formulas and hook/lifecycle limits still required task-specific coding.
This justified the small dependency selector instead of a universal evaluator.

### The five-defect integrity repair

The authoritative issue list supplied by the user described four MEDIUM defects
and one LOW defect. All five were independently reproduced at `58287e6`:

1. A nested component value could contradict its native binding; invocation
   sites could be mistaken for numeric literal proof.
2. Native evidence accepted absent/empty JAR identities.
3. Python assertions disappeared under optimization, bypassing checks.
4. Malformed structures/nonfinite values could raise outside the JSON protocol.
5. Unqualified witness resolution failed to validate explicit witness IDs.

Repairs require literal/component agreement, schema-aware native/Vanilla/reference
pins, explicit runtime validation, safe structured errors and witness-ID checks
on both paths. Supported item modifier, Digger/Sword argument variants and
historical opaque JVM nonfinite operands remained legitimate; verification was
not weakened. Seven corruption variants fail safely after repair across three
Python modes. Nine focused tests and 2,867 unchanged valid retrievals provide
bounded regression evidence. Full details: [repair validation](../mod-intelligence-v1-repair-validation.md).

## V1.5: selected dependencies and executable consumption

This name denotes the selected-obligation capability plus its animation-clock
validation, not a separate rewritten retrieval engine. Selection uses canonical
mechanic mappings and affected IDs; missing hashes remain explicit, and file-only
references are not promoted to native evidence. Sugar Rush resolves 18 Citadel
witnesses / 82 method identities. The Corrodent clock diagnostic tests cancelled
Start, server send intent, local advance, equality expiration, overshoot and
client behavior. Its 43,834 response bytes are a workload measurement only.

## V2.0 and the coding-target prototype

V2.0 adds bounded `impact` and compact `context` on V1 validation. It distinguishes
confirmed dependencies, evidence-backed relationships, possible impact and
UNKNOWNs. Peer occurrence does not prove a required edit. Tests are associations
with `NOT_RUN`, not proven future coverage. Exact fixture file/symbol mappings
are pinned; production correspondence is unknown.

The subsequent [impact prototype](../mod-intelligence-impact-prototype.md) adds
`impact --target FILE#SYMBOL` over the same mapping infrastructure. It does not
create a persistent graph, production mapper or new research capability.

## V3: bounded Change Plans

[V3](../mod-intelligence-v3.md) accepts explicit scalar/vector numeric requests.
It connects selected literals, coupled uses, current contracts, preservation
obligations, proposed edit locations and validation scenarios. Prose is not used
to infer a value or arbitrary implementation. Verified current facts remain
separate from proposed actions requiring review. Missing bindings and incomplete
source/test mapping remain UNKNOWN. Successful-response budgets fail explicitly
rather than discarding required constraints.

## V4: adaptive projection, with a deliberately narrow scope

[V4](../mod-intelligence-v4.md) adds `plan --adaptive` over a fully validated V3
plan. Three finite, pinned profiles partition REQUIRED, CONTEXT, EXCLUDE and
UNKNOWN information for selected numeric literal edits. Gates are retained by
structure, not guessed from names. Broader edits require restored contracts;
EXCLUDE is not proof of runtime independence. The default `plan` remains V3.

Four examples and 45 protected comparisons validate bounded preservation.
Larger response reductions for movement/ambiguous intent did not imply model
usage savings. Coding benchmarks later demonstrated the scope mismatch: batch
APIs and client-action traces needed behavior outside a literal-only projection.

## Post-V4 experiments and Task Preflight

The project evaluated manual discovery versus V2, V3 versus V4, Astra Medium
versus user-identified Sol Extra High, Astra Medium versus Astra Extra High, and
normal versus constrained Medium workflows. [The experiment ledger](experiments.md)
preserves all outcomes and their controls, including negative/inconclusive ones.

The economic-workflow rules did not reduce calls/files and lost an overflow
boundary outside frozen tests. Analysis therefore selected deterministic task
scope preparation—not an LLM or model router—as the smallest next experiment.

Task Preflight adds a strict manifest, file/source-pin checks and explicit routing
outside unchanged V4. Literal-only tasks use V4; broader tasks use full V3
immediately; unresolved scope/questions yield NEEDS_EVIDENCE. A compact task brief
accompanies the complete plan. It neither executes tests nor proves test coverage,
installed JAR identity or real source mapping. A read-only replay reduced five
retrieval requests to three, but the subsequent fresh A/B run did not reproduce
a call-count saving because a preflight response had to be repeated.

The wrapper, tests and three examples were completed locally before this archive.
This archive commit publishes that existing work; it does not introduce a new
intelligence version or adopt the wrapper by default.
