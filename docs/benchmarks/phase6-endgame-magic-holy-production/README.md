# Phase 6 Magic/Holy production acceptance

This directory is reserved for production-path acceptance evidence. It does not replace or alter the accepted calibration A-I artifacts.

## Checkpoint status

- P1: production Stage policy, optional existing-L2 adapter, live native generic-health formula, and synchronous event context implemented.
- P2: production generic-hostility-health participation is registered through the optional reflection bridge and scoped to exact `tensura.magic` / `tensura.holy_damage` source identities. The normalization is `N = 1 + Q * (H - 1)` at L2 `PRE_NONLINEAR` priority 7435.
- P3: actual Dementor-bearing targets receive `nativePost + RD * (pre - nativePost)` immediately after L2's native Dementor reducer at `PRE_NONLINEAR` priority 7437. Targets without Dementor receive no RD modifier.
- P4: actual Adaptive-bearing targets receive factor negotiation `A + RA * (1 - A)` after L2's native factor at `POST_MULTIPLICATIVE` priority 7437. TNO does not inspect or mutate Adaptive rank, capacity, count, memory, or source key.
- P5: integrated production acceptance complete.
- P6: production review, optional-L2 startup verification, final validation, and documentation complete.

P1 is intentionally behavior-neutral: the context is not yet connected to the native event and no L2 damage modifier is registered. The adapter uses `getExisting`, requires an initialized attachment, reads the target's current level plus live `healthFactor`, `exponentialHealth`, and entity `healthScale`, and returns no view if any required read fails.

P2 connects that context only around the already-admitted native `AdditionalDamageEntity` call, after Curve C and matching Tensura Resistance recovery. Matching Nullification prevents the context from opening. No DamageSource, tags, Tank/SHP state, or final damage is replaced or derived.

## P5 integrated production acceptance

The committed evidence comprises 86 cases and 860 real Royal Arrow releases:

| Family / target | Cases | Rows | Coverage |
|---|---:|---:|---|
| Magic / Orc Disaster | 39 | 390 | S0-S7 at L2 Lv300/600/800/1000, plus S7 controls without Dementor and (where present) Adaptive |
| Holy / Orc Disaster | 39 | 390 | same |
| Magic / Luminous Valentine | 4 | 40 | S4-S7 at L2 Lv1000 with matching Magic Resistance |
| Holy / Luminous Valentine | 4 | 40 | S4-S7 at L2 Lv1000 with matching Holy Resistance |

Every row independently reproduced live `H`, generic normalization, native-plus-negotiated Dementor, native-plus-negotiated Adaptive, and the final family-event amount. All 86 cases completed without `case_error`; all 860 rows retained one `minecraft:arrow` physical event and one native family event (`tensura:magic` or `tensura:holy_damage`). Duplicate events, recursion, unexpected Tensura bypass, and unexpected L2 bypass were all zero. APO was `NONE`, Mark was disabled, and the production feature was active without `tno.phase6.calibration`.

S0-S4 retained exact negotiation no-op parameters. Across both families, accepted-profile DPS was strictly S5 < S6 < S7 at each of Lv300, Lv600, Lv800, and Lv1000, so there is no Lv800 activation cliff. Dementor remained harmful in all eight paired S7 controls; Adaptive remained harmful in all six paired S7 controls where it exists. Native Regenerate, Tank, and Dispell classification were only observed and were not modified.

Luminous retained matching Resistance throughout. Penetration was exactly 0% at S4, 25% at S5, 50% at S6, and 100% at S7. Matching Nullification is an absolute pre-context admission gate; no selected Magic/Holy runtime target carried matching Nullification, so that contract is covered structurally and by the focused policy test rather than claimed as a natural runtime occurrence here.

The production policy and native-event gate reject Soul Eater, Elemental/Slotting, Energy Steal, and Severance before any matching-defense read or L2 endgame context is opened. Their established Phase 6 behavior is unchanged. Physical Royal Arrow/APO damage is outside the exact native family-source filter, so this layer does not scale it.
